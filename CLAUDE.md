# CLAUDE.md — browser-research-agent

## What This Is

A general-purpose agent that populates a product distributor's catalog by researching each product on the manufacturer's website. It uses a real browser (Playwright MCP) to handle JS-rendered pages, CDN blocks, and TLS issues that defeat raw HTTP scrapers.

The distributor represents many manufacturers and needs a rich local catalog — descriptions, images, brochure PDFs, demo videos — so customers stay on the distributor's site and are funneled toward a sale rather than sent to the manufacturer directly.

The agent is catalog-agnostic. It works through a two-way bridge:
- A **read skill** (per catalog) reads the current catalog, diffs it against what's needed, and produces `input.json`
- A **write skill** (per catalog) reads the approved `approved.json` and applies it back to the catalog

The Sweep & Vac website (`../Sweep and Vac/website/`) is the first catalog implementation.

---

## Why This Exists

Raw HTTP fetch-based scrapers fail constantly on modern manufacturer sites:
- JavaScript-rendered pages return empty shells
- CDNs and WAFs return 403 on automated HTTP clients
- TLS cert issues block connections outright
- Product pages move, get renamed, or get discontinued — sometimes the product itself is discontinued

Running a real browser (Playwright) solves the rendering problem. When the agent does fail, it logs the failure cleanly rather than blocking — the review UI surfaces failures for the human to resolve before the next run, including the option to remove defunct products from the catalog entirely.

## Tech Stack

- **Runtime:** Node.js 20+
- **Claude API:** `@anthropic-ai/sdk` — model `claude-sonnet-4-6`
- **Browser:** `@playwright/mcp` — Playwright MCP server; agent controls real Chromium via MCP tool calls
- **Review UI:** plain HTML + JS served by a local `http.createServer` — no framework
- **No build tools** — plain Node.js, no TypeScript, no bundler

## Full Workflow

### Step 1 — Generate input (read skill)

Run `node customers/sweep-and-vac/read-catalog.js`. It:
- Reads `../Sweep and Vac/website/data/products.js` and `data/manufacturers.json`
- Reads `../Sweep and Vac/website/brochures/manifest.json`
- For each product, determines what's missing: description, brochure
- Writes `customers/sweep-and-vac/input.json` — all products in the filtered set

### Step 2 — Research (agent)

Run `node agent.js --customer sweep-and-vac`. For each item in `input.json`:

1. If `manufacturerProductUrl` is set, navigate there first; otherwise search by manufacturer + product name
2. If `descriptionNeeded`: extract a 2–3 paragraph English B2B description. Convert dry spec lists into benefit-oriented sentences (e.g. "14-inch blade, 8hr battery" → "The unit's wide 14-inch cutting area and long-running battery..."). Do not fabricate specs not present on the page.
3. If `brochureNeeded`: check the page for downloadable PDF links — record the URL
4. Always: check for good product images (record URLs), and for YouTube product video links (record video IDs)
5. On failure after 2 attempts (404, blocked, JS wall, no results): log `status: "stuck"` with a reason note and move on — do not block the run
6. Write each result to `output.json` immediately — partial runs survive restarts; completed IDs are skipped on re-run

### Step 3 — Review UI

When the agent finishes (or is interrupted), run `node review-server.js --customer sweep-and-vac`. It serves a local HTML page on `localhost:3001`.

The review server loads both `output.json` and the current catalog state so it can show only what is **new or changed** — not the full catalog.

**For each `done` product, the UI shows:**
- Proposed description (editable textarea)
- All product images — existing catalog images and any new ones found — with individual radio (primary) and checkbox (include) per image
- YouTube IDs found (with accept checkbox)
- Brochure PDF link (with accept checkbox)

**For each `stuck` product, the UI shows:**
- The failure reason (e.g. "404 on schwarze.com — model may be discontinued")
- Three choices:
  - **Provide URL** — reviewer pastes a direct URL; stored in `approved.json` for the next agent run
  - **Skip** — leave the product as-is in the catalog, mark resolved
  - **Remove from catalog** — flags the product for deletion in `approved.json`

When the reviewer is satisfied, they hit **Submit**. The review server writes `approved.json` and calls `write-catalog.js`.

### Step 4 — Apply to catalog (write skill)

`write-catalog.js` reads `approved.json` and:
- Updates `descEn` for accepted descriptions; also generates `descEs` and `descFr` via Claude API and writes all three
- Downloads accepted images to `img/products/[id]/` and updates the `images` array in `products.js`; replaces existing images if the reviewer chose to swap them
- Adds accepted YouTube IDs to `youtubeId`
- For accepted brochures: downloads the PDF to `brochures/[id]/brochure.pdf` and adds the product ID to `brochures/manifest.json`
- Adds `manufacturerProductUrl` to the product object if newly discovered
- Removes products flagged `action: "remove"` from `products.js`
- Runs the image integrity check after writing (grep-based, per CLAUDE.md in the website repo)

## Catalog Bridge — Per-Customer Skills

Each customer directory contains two skills that know the specific catalog format:

### `read-catalog.js` interface
- Reads the current catalog and brochure state
- Outputs `input.json` with one entry per product in the filtered set

### `write-catalog.js` interface
- Reads `approved.json`
- Patches the catalog in place — updates only the approved fields per product
- Handles translations (calls Claude API for ES/FR before writing)
- Handles brochure download + manifest update (see Brochure Notes)
- Handles image replacement when the reviewer swapped old images for new ones
- Handles product removal for defunct products

### Adding a new customer
Create `customers/[customer-slug]/read-catalog.js` and `write-catalog.js` implementing the same interface. The agent and review server are catalog-agnostic — they only read/write `input.json`, `output.json`, and `approved.json`.

## Brochure Notes (Sweep & Vac specific)

The S&V product modal resolves a brochure path in this priority order:

1. **`p.brochureUrl`** on the product object — explicit external URL; skips all other logic. Only used for PDFs hosted elsewhere.
2. **`p.brochureId`** on the product object — redirects to a *different* product's local directory (`brochures/[brochureId]/brochure.pdf`). Used when two products share the same PDF (e.g. a product family brochure).
3. **Default** — `brochures/[p.id]/brochure.pdf`. No field needed on the product object.

Visibility of the brochure link is controlled by `brochures/manifest.json` — a JSON array of product IDs (or `brochureId` values) that have a local PDF. The link is hidden unless the ID appears in the manifest. The manifest is built by `build.sh` by scanning the `brochures/` directory, so dropping a PDF in the right place and rebuilding is sufficient — no manual manifest edit needed.

`write-catalog.js` handles brochures by: downloading the PDF to `brochures/[id]/brochure.pdf`, then adding the `id` to `manifest.json` directly (without waiting for a build step), so the result is immediately correct.

## Input / Output Format

### input.json (written by read skill)
```json
[
  {
    "id": "product-slug",
    "manufacturer": "Brand Name",
    "name": "Product Display Name",
    "manufacturerProductUrl": "",
    "descriptionNeeded": true,
    "brochureNeeded": true
  }
]
```

### output.json (written by agent)
```json
[
  {
    "id": "product-slug",
    "descEn": "English description, 2–3 paragraphs, no bullet lists.",
    "manufacturerProductUrl": "URL where content was found (new or confirmed)",
    "images": ["https://...1", "https://...2"],
    "youtubeIds": ["abc123"],
    "brochureUrl": "https://direct-pdf-link.pdf",
    "status": "done | stuck",
    "stuckReason": "why it failed — shown in review UI"
  }
]
```

### approved.json (written by review UI on Submit)
```json
[
  {
    "id": "product-slug",
    "action": "update | remove | retry",
    "acceptDesc": true,
    "descEn": "possibly edited by reviewer in the UI",
    "acceptImages": ["https://...1"],
    "replaceImages": true,
    "acceptYoutubeIds": ["abc123"],
    "acceptBrochure": true,
    "brochureUrl": "https://...",
    "retryUrl": "https://... (set when reviewer provides a URL for a stuck product)"
  }
]
```

## Development Notes

- `agent.js` is thin orchestration — it drives the Claude API tool loop and writes `output.json`; all research behavior is in the system prompt, inlined as a template literal in `agent.js`
- `review-server.js` serves on `localhost:3001` by default; `--port` flag to override
- The stuck threshold (2 attempts) is configurable via `--max-attempts N` on `agent.js`
- Completed IDs in `output.json` are skipped on re-run — safe to restart after interruption
- The review UI shows only diffs (new/changed fields), not the full catalog state
- `retryUrl` entries in `approved.json` are merged back into `input.json` for the next agent run — `write-catalog.js` handles this before applying other changes
